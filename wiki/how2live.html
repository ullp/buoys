How to Go Live

Internal operator document for Buoys live streaming. This file is intended to stay in the project structure only and should not be exposed as part of the public site.

Read this first:
  • The previous public live.html was not actually ready as a public production page because it exposed internal streaming setup and operator controls.
  • Use this document as the setup reference, and keep the public page limited to viewer-safe information only.
  • Do not publish admin tokens, stream keys, private endpoints, or internal notes.

1. What you need before going live

  • A deployed AWS live backend from the infra/ folder
  • A valid live_admin_token
  • A configured live_stream_key
  • The Terraform output for live_session_endpoint
  • A Chromium-based browser for best IVS broadcast compatibility
  • Stable internet, power, camera, and microphone/audio routing
  • OBS Studio installed on the operator machine
  • A webcam connected and recognized by macOS
  • A clean studio audio feed from REC OUT, MAIN OUT, or mixer USB audio
  • An audio interface or mixer USB connection if the laptop has no clean line-level input

2. Recommended physical signal chain

Preferred setup

  1. Audio: Mixer REC OUT → audio interface line input → OBS Audio Input Capture
  2. Video: USB webcam → OBS Video Capture Device
  3. Streaming: OBS → IVS ingest server + stream key

Fallbacks

  • If the mixer has USB audio, use that directly instead of a separate interface.
  • If REC OUT is unavailable, use MAIN OUT only if levels are stable and not affected unexpectedly during the show.
  • Do not rely on the laptop mic or webcam mic as the main source unless it is emergency backup only.

4. Pre-flight checklist

  1. Confirm the operator machine is on reliable power.
  2. Use wired internet if possible.
  3. Close unnecessary apps and browser tabs.
  4. Disable notifications, sleep mode, and auto-updates.
  5. Check camera framing, light, and focus.
  6. Confirm the intended audio input is the studio mix, not the laptop mic by mistake.
  7. Verify there is no clipping in the source chain.
  8. Open System Settings → Privacy & Security and confirm OBS/browser camera and microphone permissions are allowed.
  9. Put the phone on silent and avoid incoming call notifications on the operator machine.

5. OBS setup for webcam + studio audio

Create the OBS scene

  1. Open OBS Studio.
  2. Create a scene named Buoys Live.
  3. Add Video Capture Device and choose the webcam.
  4. Add Audio Input Capture and choose the audio interface, mixer USB audio device, or line input carrying the studio mix.
  5. If OBS also auto-added your MacBook mic or webcam mic, mute or remove those extra sources.

Set audio levels

  • Play music or speak through the real studio path.
  • Watch the OBS meters and aim for normal peaks around -12 dB to -6 dB.
  • Avoid red clipping at all times.
  • If necessary, lower gain on the interface or mixer output before adjusting aggressively in software.

Useful OBS filters

  • Add a Limiter to the main studio audio source.
  • Optional: add mild compression only if the stream is too dynamic.
  • Do not over-process the studio mix if the mixer output is already balanced.

6. Credentials and backend preparation

API base URL

Take the Terraform live_session_endpoint output and remove the trailing /live/session. Use only the remaining base URL.

Admin token

Use the exact value configured as live_admin_token. Keep it private and rotate it if it has been shared or shown publicly.

IVS stream key

Ensure live_stream_key is configured correctly in deployment variables and matches the live channel in AWS.

7. Stream startup workflow

  1. Open the operator version of the live control interface locally or in a protected environment.
  2. Paste the API base URL.
  3. Enter the live admin token.
  4. Click Prepare Stream.
  5. Confirm the playback URL and ingest details are returned correctly.
  6. Copy the returned ingest server / stream URL and the stream key into OBS Settings → Stream.
  7. Back in OBS, confirm webcam preview is visible and the studio audio meters are moving.
  8. Click Start Streaming in OBS.
  9. If the protected operator page also has a Go Live action, use it only if your backend workflow requires that separate activation step.
  10. Watch both the local preview and the public playback output for the first minute.

8. Quick troubleshooting

No webcam picture

  • Reconnect the webcam.
  • Close other apps that may be using the camera.
  • Re-check OBS camera permissions in macOS.

No audio from studio mix

  • Confirm the cable really comes from REC OUT, MAIN OUT, or the intended USB mixer feed.
  • Check the selected OBS audio device.
  • Check interface gain and make sure the input is not muted at hardware level.

Audio is distorted

  • Lower mixer output or interface gain.
  • Keep OBS out of the red.
  • Prefer hardware gain correction over heavy software attenuation.

Stream starts but public page is blank

  • Verify the playback URL was returned during preparation.
  • Check that the public page is using the viewer playback URL, not ingest details.
  • Give the platform a short warm-up window for the first live signal.

9. What “ready” actually means

The setup is only truly ready when all of the following are true:

  • The infrastructure has been deployed successfully.
  • The live session endpoint responds correctly.
  • The admin token works.
  • The IVS stream key is valid.
  • Camera and audio devices are recognized.
  • OBS is showing the correct webcam image.
  • OBS is showing the correct studio audio input, not the wrong microphone.
  • The playback preview confirms end-to-end delivery.

Based on the previous public page alone, readiness was not guaranteed — the page mostly documented the workflow, but did not prove the live system was safely or fully operational.

10. Suggested run of show

  • T-30: technical check, audio path, framing, bandwidth
  • T-15: backend prep, verify playback URL
  • T-05: final silence, notifications off, performers ready
  • LIVE: start stream and monitor first minute carefully
  • END: stop cleanly and note any issues for next time
